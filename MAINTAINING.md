# Maintaining jellyfin-py

Everything under `jellyfin/` and the packaging files (`pyproject.toml`, `setup.py`, `README.md`, ...) are generated by `./generate.sh`. Never hand-edit them; CI fails if the tree differs from generator output.

Inputs live in `versions.env` (generator version, spec URL/hash) and `templates/` (override for openapi-generator bug #16071; drop once PR #25540 ships in a release).

## Version policy

The package version is the Jellyfin API version (`info.version` of the spec).

- `sync-spec.yml` polls the spec daily. A new `info.version` opens a PR whose commit carries `Release-As: <version>`; merge it with rebase or a merge commit so the footer survives.
- Renovate bumps `GENERATOR_VERSION`; `regenerate.yml` commits the regenerated client. These are `chore(deps)` commits and do not release by themselves.
- A client-only fix that must ship before Jellyfin moves: push a commit with the footer `Release-As: <version>.post1`.
- release-please then opens a release PR; merging it tags the release and publishes to PyPI.

## One-time setup

1. Install the Renovate GitHub App on the repository.
2. On PyPI, add a trusted publisher for this repository (workflow `release.yml`, environment `pypi`), and create the `pypi` environment in GitHub.
3. Allow GitHub Actions to create pull requests (Settings → Actions → General). PRs opened with `GITHUB_TOKEN` do not trigger CI; use a PAT or GitHub App token if you want checks to run on them.
